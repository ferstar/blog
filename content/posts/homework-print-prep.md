给娃打印作业大概是不少家长的日常：老师把作业拍照发群里，照片是歪的、边上带着小程序角标，横的竖的混在一起，直接打印出来惨不忍睹。扫描 App 我也试过，但它们的目标是"归档扫描件"——输出的是扫描风图片，带水印，也不管 A4 排版。

所以我做了个更窄的东西：**作业打印助手**。上传 PDF 或照片，它负责把纸拉平、去掉正文外的角标、把页面转正、铺满 A4，预览确认后下载打印版 PDF 或直接打印。在线版跑在我自己的 VPS 上（[dazuoye.ferstar.org](https://dazuoye.ferstar.org)），代码开源在 [github.com/ferstar/homework-print-prep](https://github.com/ferstar/homework-print-prep)。

## 处理管线

每页走同一条链路：

{{< mermaid >}}
flowchart LR
    A[上传 PDF / 照片] --> B[前端把图片<br>合成 PDF]
    B --> C[透视拉平]
    C --> D[去角标]
    D --> E[OCR 摆正]
    E --> F[裁近内容框]
    F --> G[铺满 A4]
    G --> H[全文方向统一]
    H --> I[预览微调 / 导出]
{{< /mermaid >}}

几个环节展开说：

**透视拉平**。手机拍的作业纸先找纸缘：闭合边框 → 内容 hull → 纸缘回退，拿到四边形后 `getPerspectiveTransform` + `warpPerspective` 一步拉平。相机直拍（浏览器读 EXIF 上报）改成纸缘优先，用 GrabCut 抠纸，桌面背景杂乱也不怕。麻烦的是微信转发的照片——EXIF 被压掉了，服务端就判一次：找到一张歪着的纸、且纸外不是纯色数字背景，才按照片流程走，否则按截图处理不裁剪。自动拉不平时，预览页有个 Office Lens 式的四角编辑器，拖四个角手动框，框完即定稿、不再二次裁剪。

**去角标**。作业页边上常见小程序 logo、横幅文字、青色 CS 印记。做法是先估内容框，只对框外的孤立小连通域聚类，用局部纸色填充擦掉；QR 和青色印记会扩展成整块板一起擦。内容框内的教育二维码、页码、密封线一概不动——这些是作业本身的一部分。

**OCR 摆正**。对 0/90/180/270 各跑一遍内嵌的 Rust OCR（ocr-rs + MNN，PP-OCRv6 tiny 模型编译时校验后直接内嵌，运行时不联网），按置信度加文字行分数选最佳方向。整本处理完再做一次全文档方向统一：按阅读方向多数票定横竖，个别页旋转重铺，不会盲目把横版作业改成竖版。

**纸白增强**默认关闭。灰纸照片想提亮可以开启：形态学估计纸面光照后软提亮，不做二值化，尽量保住铅笔和灰字。但它对淡笔迹有伤害风险，而且光照估计开销不小，所以默认不开，开启后也要求打印前检查预览。

## 几个工程决定

**软失败哲学**。透视、摆正、纸白每个增强环节不可靠时都返回原图加原因，绝不抛异常中断整页。拍摄角度太刁钻、检测几何退化、OCR worker 崩溃，结果都是"这页保持原样"而不是整个任务失败。对这类图像算法来说，宁可少做也不能做错——把纸拉变形比不拉糟糕得多。

**每页一个无损缓存**。调边距、开关纸白这类调整，复用摆正、去角标、裁切之后的无损 PNG，不重跑 OCR。缓存键包含页面设置和 `CACHE_VERSION`，改预处理算法或换内置模型就递增版本号整体失效。

**单机也要限流**。重处理是 CPU 密集操作，上传、单页重处理、批量重处理、擦除、导出共享一个 FIFO 有界队列：默认同时 1 个、排队 4 个，满了返回 429、等待超时返回 503，网页显示重试倒计时并保留这次操作和已上传的文件。文档走 Cloudflare R2 直传加 CDN：浏览器用五分钟有效的签名 PUT 直传，下载走 CDN，用户上传下载都不占 VPS 带宽，导出 URL 带内容哈希不会命中旧版本。

**反馈闭环**。每页可以点赞点踩，切换反馈时把当时的页面参数、处理指标和预览版本一起存进 SQLite。文件按反馈分类保留：点踩 30 天、点赞 7 天、无反馈 1 天——点踩的样本留最久，攒着当回归用例。

**测试靠合成场景**。真实作业数据不能入库，回归就靠脚本生成带区域标注的中文合成试卷：有框/无框、单栏/双栏、稀疏/贴边内容、淡笔迹、阴影、旋转、透视共 36 个精选场景，导出对比图加区域保留指标（拼音、公式、细线、页码、二维码是否还在）。真实样本走 GitHub Release 分发、解压到 gitignore 的 `fixtures/`，本地跑端到端检查。

## 技术栈与部署

后端 FastAPI + OpenCV + PyMuPDF，Python 3.14，uv 管理（src 布局，`uv sync` 时顺带编译 Rust OCR worker）；前端 React + TypeScript + shadcn/ui，Vite 构建产物打进 wheel，生产运行只需要 Python。OCR worker 是常驻子进程，串行复用，超时或崩溃自动重启。部署就是一个小 VPS 加 Docker，单进程 uvicorn——队列是进程内的，多 worker 会各自为政，这也是刻意的：与其分布式，不如把单机做扎实。

## 已知边界

导出是约 160 DPI 的栅格 PDF，不是矢量；弯曲书页展平不支持，没有可靠纸缘或外框时透视校正保守回退，可能保留轻微梯形；极淡铅笔在纸白增强下仍可能偏浅。这些 README 里都写明白了，不装全能。

整个项目从第一个 commit 到 1.0 上线用了三天，大部分时间其实花在四角编辑器和排队这些"不酷"的地方。但用户感知最好的恰恰也是这些：拉不平时能手动拖角，高峰期排队不用重新上传。
